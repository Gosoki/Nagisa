# 渚 Nagisa

**一座随时可以约人上岛的线上小岛。**

打开网页、起个名字就上岸了。岛上有人在码头钓鱼，有人在广场玩○×问答，神社前有人抽签，天黑后海滩上空会放烟花。你可以跟着朋友走、悄悄话、猜拳、掷骰子，也可以开一座只属于你们的私人小岛，把链接发给朋友，大家落在同一座岛上。

整座岛——地形、建筑、角色、音乐和音效——全部由代码生成，没有任何美术资源文件；画面是手绘墨线风格。

## 适合拿来做什么

| 场景 | 怎么用 |
|---|---|
| **朋友线上小聚** | 「岛屿」面板 → 创建私人小岛 → 复制邀请链接发到群里。大家进来后一起逛、聊天、钓鱼、玩问答，最后在海滩看烟花、拍张照。 |
| **远程团队的茶水间 / 晨会** | 岛上每天（真实 90 分钟一个昼夜）自动排好日程：早会签到、问答、集市、钓鱼大赛……管理员也可以随时加开一场。 |
| **社团活动 / 线上活动** | 主持人在舞台所在区域开始活动、发公告、看签到人数；○×问答自动主持、自动判定。 |
| **一个人待着** | 坐在茶屋的榻榻米上看天色变化，去灯塔眺望，集齐全岛印章，把鱼类图鉴补满。 |

## 岛上能做的事

### 小游戏

- **○×问答**（广场）——题目出现后，认为「对」就跑进 ○ 圈，认为「错」就跑进 × 圈；倒计时结束时服务器按你**站的位置**判定，答错出局，坚持到最后的人获胜。题库 90 题，中日英三语。
- **钓鱼**（四个码头尽头和海滩）——按 E 抛竿，浮漂沉下去时再按 E 提竿。18 种真实的日本近海鱼类，外加一只旧靴子，有稀有度和尺寸，夜里会钓到不一样的鱼。黎明时分的「钓鱼大赛」按最大单条尺寸排名。
- **御神签**（神社）——每天（按日本时间）抽一次，重抽还是今天那张签；抽到大吉有徽章。
- **印章集章**——八个地方各有一个印章台，集齐获得「环岛旅人」徽章。小地图上会标出还没盖的印章台。
- **猜拳**——点开附近某人的名片发起挑战，双方都出拳后服务器才揭晓，平局自动再来。
- **烟花**——站在海滩或南港就能放一发；夜晚的「花火大会」会自动放一场。
- **敲钟**——岛上四口钟，附近的人都听得到（有空间方位的钟声）。
- **天气**——全岛同一片天，每 15 分钟一段，晴、阴、雨轮换；下雨时有雨丝和雨声，雨天鱼更容易上钩。
- **骰子**——聊天里输入 `/roll` 或 `/roll 6`。
- **深夜寻宝**——岛上随机埋着三件宝物。在任何地方按 F（或点「挖」），沙子会告诉你离最近的宝物是烫、温、凉还是冰；别人挖的冷热也会显示在他们头顶，看到有人挖出「🔥」就赶紧凑过去。挖到的人上排行榜，累计挖到 3 件获得「寻宝达人」徽章。

### 社交

- **悄悄话**：`/w 名字 内容`，`/r 内容` 回复上一条悄悄话，点悄悄话里的名字可快速回复。
- **玩家名片**：点人员列表里的名字，或直接点画面里的人 → 跟随、猜拳、悄悄话、屏蔽、加好友；管理员还能禁言、踢出、指定主持人。
- **好友**：在名片上加好友，对方同意后互为好友。人员面板里能看到好友是否在线、在哪座岛，点「去找 TA」直接过去（包括私人小岛）；好友上岛时会收到提示。
- **留言板**：走到公告栏前可以留一句话（80 字以内），重启后还在。
- **徽章与称号**：八种徽章，可以选一个戴在名字下面。
- **拍照**：「更多」→ 拍照，保存当前画面（不含界面）。

### 活动与日程

岛上的一天 = 真实 90 分钟。每座岛（包括私人岛）都自动运行同一份日程：

| 岛上时间 | 活动 | 地点 |
|---|---|---|
| 凌晨 | 深夜寻宝（全岛都是寻宝场） | 广场集合 |
| 黎明 | 清晨钓鱼大赛 | 北港 |
| 早上 | 早会（签到） | 广场 |
| 上午 | ○×问答 | 广场 |
| 正午 | 港口集市 | 南港 |
| 下午 | ○×问答 | 广场 |
| 黄昏 | 点灯仪式（灯塔亮起） | 灯塔岬 |
| 傍晚 | 提灯夜行（每人提一盏灯笼） | 神社 |
| 入夜 | 海滩音乐会（现场生成的音乐） | 海滩 |
| 深夜 | 花火大会 | 海滩 |

活动到点会自动开始；有主持人在场时由主持人决定开始时间（最多等 3 分钟）。

## 快速开始

需要 Node 20 以上。

```bash
npm install          # 安装三个 workspace
npm run dev          # shared（监听）+ 服务端 :8787 + 客户端 :5173
```

打开 <http://localhost:5173>。再开一个窗口就能「遇见自己」。

### 管理员

服务端设置 `ADMIN_TOKEN=xxx`，然后打开 `http://localhost:5173/?admin=xxx`。令牌读到后会立刻从地址栏抹掉（只存在当前标签页），不会随截图或分享链接泄露。

私人小岛的创建者（岛主）在自己的岛上自动拥有管理员权限，下次用同一个浏览器回来时依然是岛主。

### 生产构建 / Docker

```bash
npm run build && npm start          # 服务端同时托管 API、WebSocket 和构建好的客户端

export NAGISA_ADMIN_TOKEN=$(openssl rand -hex 24)
export NAGISA_SESSION_SECRET=$(openssl rand -hex 32)
docker compose up --build
```

生产环境请务必设置 `PERSIST_PATH`（compose 里已设）：私人岛登记、各岛的日程/留言板、访客的印章/图鉴/徽章都存在这里，没有它重启后邀请链接会失效。

### 主要环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `PORT` | `8787` | HTTP + WebSocket 端口 |
| `ROOM_CAPACITY` | `120` | 每个公共分片的人数上限 |
| `ROOM_COUNT` | `1` | 启动时创建（且永不休眠）的公共分片数 |
| `PRIVATE_ROOM_CAPACITY` | `40` | 每座私人小岛的人数上限 |
| `PERSIST_PATH` | 未设置 | JSON 持久化文件；不设置则只存在内存里 |
| `ADMIN_TOKEN` | 未设置 | `?admin=…` 获得管理员；不设置则无人能成为全局管理员 |
| `SESSION_SECRET` | 随机 | 断线重连令牌的签名密钥（也接受 `RESUME_SECRET`） |
| `STATIC_DIR` | 未设置 | 构建好的客户端目录 |
| `MAX_CONNECTIONS` | `2000` | 进程接受的 WebSocket 连接总数上限 |
| `MAX_CONNECTIONS_PER_IP` | `0`（不限） | 单个客户端地址的连接上限；在反向代理后面使用时须同时设 `TRUST_PROXY=1` |
| `TRUST_PROXY` | 关 | 从 `X-Forwarded-For` 读取客户端地址（部署在 nginx/Caddy 后面时打开） |

## 测试

```bash
npm run typecheck    # 三个 workspace 全部类型检查
npm test             # 服务端单测 + 世界生成检查 + 界面挂载检查
npm run test:e2e     # 真实服务器 + 真实 WebSocket 的端到端（含全部小游戏；先 npm run build）
npm run test:app     # 真浏览器整栈：两名玩家进岛
npm run test:island  # 真浏览器：建私人岛 → 邀请链接 → 好友进岛 → 悄悄话
npm run test:roam    # 真浏览器：在岛上四处走动
npm run test:load    # 压测：150 个脚本访客走动、聊天、做表情，看 tick 耗时与带宽
npm run test:all     # 以上全部
```
